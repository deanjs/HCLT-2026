## §1. 논문이 밝힌 한계

### 1-1. 적용 범위

Python 함수 이름의 표기 규약이라는 **단일 과제**와 **합성 프롬프트**에서 얻은 결과다.
다른 지시 유형이나 실제 코드베이스로 일반화하려면 추가 검증이 필요하다.

선행 코드는 매개변수와 본문을 전 항목 동일하게 둔 합성 함수다. 실제 저장소 코드에서
같은 현상이 나타나는지는 확인하지 않았다.

### 1-2. 접두사 처리가 모델마다 다르다

준수율 측정에서 **두 모델은 접두사를 고정하지 않았고, 두 모델은 `def `를 고정했다.**

| 모델 | 접두사 |
|---|---|
| Qwen2.5-Coder · StableCode | 고정하지 않음 |
| DeepSeek-Coder · Llama-3.2 | `"def "` 고정 |

접두사를 포함하면 일부 모델에서 정상적인 생성이 이루어지지 않아, 각 모델의 생성 능력을
온전히 비교할 수 있는 프롬프트를 모델별로 채택했다. **두 조건의 차이가 준수율에 미치는
영향은 검증하지 못했다.**

조건마다 어느 쪽이었는지는 결과 JSON의 `metrics.extra.forced_prefix`로 확인할 수 있다.

### 1-3. 개입 방식이 한정돼 있다

평균 덮어쓰기와 잔차 조향, 그것도 **단일 층에 고정된 세기로** 적용한 것에 한정된다.
관측된 경로 차이(Key와 Value)가 다른 개입 방식에서도 유지되는지는 확인하지 않았다.

층 단위의 국소화만 주장하며, 어텐션 헤드나 뉴런 단위는 주장하지 않는다.

### 1-4. 되돌림률은 실제 생성을 보장하지 않는다

되돌림률은 **고정된 두 후보 사이의 상대적 선호**를 재는 지표다. 실제로 생성되는 이름이
지침을 지킨다는 뜻이 아니다. 경로별 치환의 근거로 쓴 값에도 같은 제약이 적용된다.

실제로 두 지표는 양방향으로 어긋났다. 세기 8에서는 네 모델 모두 실제 준수율이 0인데
세 모델의 되돌림률은 완전 회복을 초과했고, 세기 1에서는 되돌림률이 실제 준수율보다
낮게 측정됐다.

### 1-5. 지침의 위치 이점을 분리하지 못한다

지침이 **항상 프롬프트의 첫 부분**에 놓이는 설계다. 따라서 지침 토큰이 받는 어텐션에
섞인 위치의 몫을 분리할 수 없다. 이 관측에서 안전하게 말할 수 있는 것은 "모델이 지침을
충분히 참조한다"까지이며, 참조량이 원인이 아니라는 근거는 개입 실험에 둔다.

### 1-6. 근거에서 제외한 관측 — 선행 코드 내부의 어텐션 비교

선행 코드 안에서 준수 이름과 위반 이름의 어텐션을 비교하려 했으나, **두 표기의 위치가
모든 묶음에서 동일**하여 위치 효과가 분리되지 않았다. 위치를 반대로 배치한 대응 집합에서
차이가 사라지거나 방향이 반전되어 **주요 근거에서 제외**했다.

관측값을 `a = f(위치) + g(표기)` 형태로 보면, 배치가 고정된 한 묶음을 늘려도 위치 항이
상쇄되지 않는다. 경위는 [`step2/results.md`](step2/results.md)에 그대로 남겼다.

인과 스텝(step3·5·6)은 처치와 통제가 **같은 자리**를 건드린 뒤 차이를 취하므로 이 교란의
영향을 받지 않는다.

## §3. 실행 환경 기록의 결손

결과 11,914개 중 **3,528개(30%)에 실행 환경 기록(`meta`)이 없다.** 환경 기록 기능이
붙기 전에 실행됐기 때문이다. 기록이 있는 것도 대부분 `git_dirty: true`로, 커밋되지 않은
수정 상태에서 실행됐음을 뜻한다.

어느 폴더가 얼마나 비어 있는지는 [`환경_및_버전.md`](환경_및_버전.md) §2에 있다.

이것은 결과의 타당성 문제가 아니라 **추적성의 결손**이다. 실험 입력이 통합 하네스와
같다는 것은 [`검증_하네스등가성.md`](검증_하네스등가성.md)에서 따로 확인했다.
