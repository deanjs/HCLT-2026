# 문서 안내

코드 생성 언어모델이 함수 이름의 표기 규약 지침을 어기는 이유를 모델 내부에서 추적한
실험의 기록이다. 어텐션 **배분**과 그 위치에서 전달되는 **내용(Value)**을 분리해,
표기 신호가 어느 경로로 흐르는지 관측과 개입 양쪽에서 확인했다.

---

## 스텝별로 읽는다 — 방법론 → 결과 → 다음 실험

스텝 폴더는 전부 같은 구성이다. **`방법론.md`(무엇을 왜 어떻게) → `results.md`(무엇이
나왔나 · 끝에 「다음 실험으로」)** 순으로 읽으면 스텝 사이가 끊기지 않는다.

```
docs/<스텝>/
  README.md    이 스텝이 묻는 것 · 결과 원본 · 실행 순서
  방법론.md     방법과 순서 — 왜 하나 · 무엇을 건드리나 · 수식 · 데이터 · 한계
  results.md   결과와 해석 — JSON 읽는 법 · 표 · 그림 · 다음 실험으로
  figures/     그림 (explain_* = 이해용, 나머지 = 논문용)
```

| 스텝 | 묻는 것 | 답 | 다음으로 |
|---|---|---|---|
| [`step1`](step1/) | 선행 코드의 위반이 늘면 준수율이 떨어지나 | 임계에서 급락, 회복 없음 | 신호가 **어디로** 오나 |
| [`step2`](step2/) | 그 신호를 어텐션으로 관측할 수 있나 | **주요 결론 철회**(자리 효과) | 판정은 인과의 몫 |
| [`step3`](step3/) | Key인가 Value인가, 어느 층인가 | **Value · 후반 단일 층** | 장치 검사 + 지침도 같은가 |
| [`diag`](diag/) | 덮어쓰기가 Key를 더 망가뜨리나 (실험 아님) | 기각 — Key가 오히려 덜 줄었다 | step3 결론 확정 |
| [`step4`](step4/) | 모델이 지침을 보기는 하나 | 코드보다 더 본다 | 그 참조가 행동을 바꾸나 |
| [`step5`](step5/) | 지침도 같은 통로인가 | **Value · 층 하나** — 코드와 같은 구조 | 그러면 거기를 밀면 되살아나야 |
| [`step6`](step6/) | 값을 밀면 되살아나나 · 어텐션을 키우면 안 되나 | 셋에서 회복 · Spotlight 15/16이 0.000 | RQ1~3의 답을 닫는다 |

**실행 순서는 이와 다르다**(GPU 가벼운 것부터): step2 → step4 → step1 → step3 → step5 → diag → step6.

**step2의 주요 결론은 철회했다.** 선행 코드 안에서 준수 이름과 위반 이름의 어텐션을
비교하려 했으나 표기 배치가 모든 묶음에서 같아 위치 효과가 분리되지 않았다. 폐기하지 않고
경위를 [`step2/results.md`](step2/results.md)에 그대로 남겼다. 인과 스텝(step3·5·6)은
처치와 통제가 같은 자리를 건드리므로 이 교란의 영향을 받지 않는다.

## 답

| | 결론 |
|---|---|
| **A1** | 선행 코드의 지침 위반 사례는 모델의 지침 준수율을 감소시켰다. 다만 지침이 모델의 기본 표기 선호와 충돌할 때 두드러진다 |
| **A2** | 코드 특화 모델은 지침 토큰에 더 많은 어텐션을 할당하면서도 지침을 위반했으며, 표기 신호는 Value 경로를 통해 전달되었다 |
| **A3** | 지침 토큰의 어텐션 비중을 높이는 개입으로는 준수율을 높이지 못한 반면, 잔차 조향은 네 모델 중 세 모델에서 준수율을 높였다 |
