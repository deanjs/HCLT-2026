# 문서 안내

코드 생성 언어모델이 함수 이름의 표기 규약 지침을 어기는 이유를 모델 내부에서 추적한
실험의 기록이다. 어텐션 **배분**과 그 위치에서 전달되는 **내용(Value)**을 분리해,
표기 신호가 어느 경로로 흐르는지 관측과 개입 양쪽에서 확인했다.

## 실험 스텝

각 폴더에 `README.md`(읽는 순서) · `방법론.md`(왜·무엇을·수식) · `code.md`(개념↔코드) ·
`results.md`(결과·해석) · `figures/`가 있다.

| 스텝 | 무엇을 확인하나 | 결과 |
|---|---|---|
| [`step1`](step1/) | 선행 코드의 위반이 늘면 준수율이 떨어지나 | `results/step1_cliff/` 4,368 |
| [`step2`](step2/) | 코드 신호를 어텐션으로 관측할 수 있나 — **주요 결론 철회** | `step2_code-observe/` 334 |
| [`step3`](step3/) | 층별로 Key/Value를 치환해 인과를 확인 | `step3_code-cause/` 504 |
| [`step4`](step4/) | 모델이 지침 토큰을 실제로 참조하나 | `step4_instr-observe/` 336 |
| [`step5`](step5/) | 지침 신호를 덮어써 인과를 확인 | `step5_instr-cause/` 336 · `-control/` 2,016 · `control_sweep_*/` 672 |
| [`step6`](step6/) | 잔차 조향과 어텐션 증폭을 같은 자로 비교 | `step6_steer/` 2,184 · `-generate/` 756 · `-crosslayer/` 336 |
| [`diag`](diag/) | 측정 장치 검사 — 덮어쓰기가 Key를 더 훼손하나 (실험 아님) | `diag_kv-phase/` 72 |

**step2의 주요 결론은 철회했다.** 선행 코드 안에서 준수 이름과 위반 이름의 어텐션을
비교하려 했으나 표기 배치가 모든 묶음에서 같아 위치 효과가 분리되지 않았다. 폐기하지 않고
경위를 [`step2/results.md`](step2/results.md)에 그대로 남겼다. 인과 스텝(step3·5·6)은
처치와 통제가 같은 자리를 건드리므로 이 교란의 영향을 받지 않는다.

## 답

| | 결론 |
|---|---|
| **A1** | 선행 코드의 지침 위반 사례는 모델의 지침 준수율을 감소시켰다. 다만 지침이 모델의 기본 표기 선호와 충돌할 때 두드러진다 |
| **A2** | 코드 특화 모델은 지침 토큰에 더 많은 어텐션을 할당하면서도 지침을 위반했으며, 표기 신호는 Value 경로를 통해 전달되었다 |
| **A3** | 지침 토큰의 어텐션 비중을 높이는 개입으로는 준수율을 높이지 못한 반면, 잔차 조향은 네 모델 중 세 모델에서 준수율을 높였다 |
