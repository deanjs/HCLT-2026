# 환경과 버전

**이 실험은 라이브러리 버전에 민감하다.** 개입이 `transformers`의 KV 캐시 자료구조를
직접 편집하기 때문이고, 그 자료구조가 버전마다 다르기 때문이다. 버전이 바뀌면
"같은 실험을 다시 돌린 것"이 아니라 **다른 곳을 건드린 실험**이 된다.

---

## 1. 실제로 쓴 환경

결과 JSON의 `meta`에 `save_result`가 자동으로 기록한 값이다. 손으로 적은 것이 아니다.

| 항목 | 값 |

| GPU | Tesla T4 (Google Colab 무료 티어) |
| torch | `2.11.0+cu128` |

**기준은 `transformers==5.13.1`이다.** 기록이 남은 것 중 8,398개가 이 버전이고,

> **왜 버전이 갈렸나.** 노트북의 `!pip install -q -r requirements.txt`가 **저장소를

> 위 표의 값은 그때그때 Colab 기본값이다. 지금은 설치를 클론 뒤로 옮기고, 버전이
> 어긋나면 예외로 멈추는 검사를 붙였다(§3).

## 2. 알려진 한계 — 기록이 비어 있는 결과

**3,528개(전체의 30%)에 `meta`가 없다.** 초기 실행이 환경 기록 기능이 붙기 전에
이루어졌기 때문이다.

| 폴더 | 기록 없는 개수 |
|---|---|
| `step1_cliff` (Qwen2.5-Coder·StableCode 몫) | 2,184 |
| `step3_code-cause` | 504 |
| `step4_instr-observe` | 336 |
| `step5_instr-cause` | 336 |
| `step2_code-observe` | 168 |

이 결과들이 어떤 버전에서 나왔는지는 파일만으로 확인할 수 없다. 다만 같은 시기에
같은 노트북으로 돌렸으므로 `5.13.1`로 추정한다. **추정이며 확인된 값이 아니다.**

또 하나. `meta`가 기록된 결과도 대부분 `git_dirty: true`다. 커밋되지 않은 수정 상태에서
실행했다는 뜻이므로, `meta.git_sha`가 가리키는 커밋이 실행 당시 코드와 정확히 같다고
보장할 수 없다. 커밋 자체는 `local/*` 태그로 전부 보존돼 있다.

## 3. 설치

```bash
pip install -r requirements.txt
```

`requirements.txt`는 위 §1의 값으로 고정돼 있다. **버전을 바꾸지 말 것.**

노트북에서는 셀 ③(저장소 클론)이 클론 직후에 같은 파일을 설치하고, 이어서 **버전을
검사해 어긋나면 예외를 던진다.** 조용히 다른 버전으로 도는 일을 막기 위한 것이다.

```
라이브러리           요구            지금
torch           2.11.0        2.11.0
transformers    5.13.1        5.13.1
버전 일치 - 진행합니다
```

어긋나면 이렇게 멈춘다.

```
RuntimeError: 라이브러리 버전이 요구와 다릅니다: transformers
```

Colab에서 설치가 새 버전을 받았다면 **런타임 > 세션 다시 시작** 후 첫 셀부터 다시
실행해야 반영된다.

집계·작도만 할 것이라면 GPU도 torch도 필요 없다. `numpy`와 `matplotlib`만 있으면
`results/`의 JSON에서 논문의 표와 그림이 전부 다시 나온다.

```bash
pip install numpy matplotlib
```

한글 라벨 그림(`paper_figures_ko.py`)에는 나눔 계열 글꼴이 추가로 필요하다.

| OS | 설치 |
|---|---|
| macOS | `brew install --cask font-nanum-gothic` |
| Ubuntu/Debian | `sudo apt-get install fonts-nanum fonts-nanum-extra` |
| Colab | `!apt-get install -qq fonts-nanum` |

글꼴이 없으면 스크립트가 예외로 즉시 멈춘다(글자가 깨진 그림을 만들지 않는다).

## 4. 왜 버전을 고정하는가

`transformers`의 KV 캐시 접근 경로가 세 갈래로 갈린다.

| 버전대 | 접근 |
|---|---|
| 4.54 이상 | `cache.layers[i].keys` · `cache.layers[i].values` |
| 그 이전 | `cache.key_cache[i]` · `cache.value_cache[i]` |
| 더 이전 | 튜플 |

`src/harness/model.py`의 `_cache_kv()`가 세 갈래를 모두 처리하므로 **읽기는 어느
버전에서도 된다.** 문제는 그다음이다. 층 인덱스가 가리키는 대상, GQA KV 그룹의
묶임 방식, 캐시가 갱신되는 시점이 버전에 따라 달라질 수 있고, 이 실험은 바로 그
지점에 개입한다.

같은 이유로 어텐션 증폭(`src/harness/steer.py`)도 `ALL_ATTENTION_FUNCTIONS` 디스패치
경로에 의존한다. 이 경로를 찾지 못하면 조용히 넘어가지 않고 예외를 던진다.

## 5. 메모리

무료 티어 T4(16GB) 기준으로 설계했다.

| 모델 | 비고 |
|---|---|

| DeepSeek-Coder-6.7B | **T4에서 메모리 초과 가능.** 노트북 셀 ③에 8bit 적재 주석이 있다 |

step1의 DeepSeek-Coder는 노트북에서 조건을 둘로 나눠(`SHARD`) 런타임 두 개에서
돌리도록 되어 있다.
