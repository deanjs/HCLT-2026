# 재현 절차

두 갈래가 있다. 목적에 맞는 쪽만 하면 된다.

| 하려는 것 | GPU | 시간 | 절차 |
|---|---|---|---|
| **논문의 표와 그림을 다시 만든다** | 불필요 | 수 분 | §1 |
| **결과 JSON 자체를 처음부터 다시 만든다** | 필요 | 수십 시간 | §2 |

무엇이 무엇을 만드는지는 [`실행_대응표.md`](실행_대응표.md), 버전은
[`환경_및_버전.md`](환경_및_버전.md)에 있다.

## §1. 결과에서 표·그림을 다시 만든다 (GPU 없이)

`results/`의 JSON 11,914개가 저장소에 그대로 들어 있다. 모델을 적재하지 않으므로
노트북도 GPU도 필요 없다.

### 1-1. 받기

```bash
git clone https://github.com/deanjs/HCLT_2026.git
cd HCLT_2026
```

### 1-2. 설치

```bash
pip install numpy matplotlib
```

그림에 한글 라벨을 쓰므로 나눔 계열 글꼴이 필요하다.

| OS | 설치 |
|---|---|
| macOS | `brew install --cask font-nanum-gothic` |
| Ubuntu/Debian | `sudo apt-get install fonts-nanum fonts-nanum-extra` |

글꼴이 없으면 스크립트가 **예외로 즉시 멈춘다.** 글자가 깨진 그림을 만들지 않는다.

### 1-3. 논문 그림 4장

```bash
python scripts/paper_figures_ko.py
```

한 번에 다음이 만들어진다.

```
docs/step1/figures/ko_cliff.pdf          그림 1
docs/step4/figures/ko_attention.pdf      그림 2
docs/step3/figures/ko_intervene.pdf      그림 3
docs/step6/figures/ko_score_vs_real.pdf  그림 4
```

### 1-4. 논문 표의 수치

```bash
python scripts/step3_net_effect.py results/step3_code-cause   # 선행 코드 순효과
python scripts/step5_net_effect.py results/step5_instr-cause  # 지침 순효과
python scripts/step6_summary.py                               # 생성 준수율
```

각 스텝의 보조 집계는 [`실행_대응표.md`](실행_대응표.md) §2에 있다.

## §2. 결과 JSON을 처음부터 다시 만든다 (GPU 필요)

Google Colab 무료 티어(T4) 기준으로 설계했다.

### 2-1. 노트북 하나 열기

`notebooks/`에서 만들려는 결과에 해당하는 노트북을 연다. 어느 노트북이 어느 결과를
만드는지는 [`실행_대응표.md`](실행_대응표.md) §2에 있다.

### 2-2. 셀 순서

| 셀 | 무엇 |
|---|---|
| ① | 실험 식별 — 어느 스텝·무엇을 확인하나·메모리 주의 |
| ② | GPU 확인, 시드 42 고정 |
| ③ | 저장소 클론·체크아웃(`BRANCH = 'main'`) → `requirements.txt` 설치 → **버전 검사** |
| ④ | 조건 설정 — **여기서 모델 하나를 고른다** (`PICK`) |
| ⑤ | 실행 — 조건마다 즉시 저장 |
| ⑥ | 결과 불러오기 |
| ⑦ | 요약 · zip 내려받기 |

### 2-3. 알아 둘 것

**모델 하나씩 돌린다.** 셀 ④의 `PICK`으로 고른다. 런타임이 끊겨도 그 모델만
영향을 받는다.

**이미 저장된 조건은 건너뛴다.** 끊긴 뒤 같은 노트북을 다시 열면 남은 것부터 이어서
돈다. 조건마다 즉시 저장하므로 진행분을 잃지 않는다.

**step5·step6은 본실험 하나 + 보강 둘이다.** 순서대로 돌려야 한다. 보강 결과가 없으면
논문의 표를 만들 수 없다 — 논문의 지침 순효과는 처치와 통제의 차이이고, 생성 준수율은
보강 노트북에서 나온다.

**DeepSeek-Coder-6.7B는 T4에서 메모리 초과가 날 수 있다.** 노트북 셀 ④에 8bit 적재
주석이 있다. step1은 조건을 둘로 나눠(`SHARD`) 런타임 두 개에서 돌리도록 되어 있다.

### 2-4. 저장 경로

결과는 `results/<스텝>/<슬러그>.json` 한 곳에만 쓴다. 모델별 폴더로 나누지 않는다
(슬러그에 모델 이름이 들어 있다). 경로가 어긋나면 재개와 재분석이 통째로 멈춘다.

## §3. 저장소가 멀쩡한지 확인

결과를 만들기 전이든 후든, 아래 둘은 언제든 돌릴 수 있다.

```bash
pip install pytest
python -m pytest -q
```
→ `88 passed, 2 skipped`

```bash
bash scripts/verify_harness_equivalence.sh
```
→ `전부 일치 — 통합 하네스로 다시 돌려도 같은 실험이 된다`

두 번째는 통합 하네스가 각 실험 당시의 하네스와 **같은 실험 입력**을 만드는지 검증한다.
자세한 내용은 [`검증_하네스등가성.md`](검증_하네스등가성.md)에 있다. torch·numpy·pytest
없이 순수 파이썬으로 돈다.

## §4. 자주 걸리는 것

| 증상 | 원인 · 해결 |
|---|---|
| 그림 스크립트가 글꼴 예외로 멈춤 | 나눔 글꼴 미설치 → §1-2 |
| `No module named pytest` | `pip install pytest` |
| `python: command not found` (macOS) | 검증 스크립트는 `python3`을 먼저 찾는다. 그래도 안 되면 `PYTHON=python3 bash scripts/...` |
| 노트북이 결과를 새로 안 만듦 | 정상이다. 이미 저장된 조건은 건너뛴다 |
| `results/` 경로 오류 | 저장소 **최상위**에서 스크립트를 돌려야 한다 |
