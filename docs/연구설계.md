# 연구 설계 — 질문 · 고정 설정 · 스텝 사슬

전체 지도다. 스텝 하나를 처음부터 보려면 `docs/<스텝>/README.md`로 간다.

---

## 1. 무엇을 밝히려는가

**큰 질문:** 코드 생성 언어모델은 "함수 이름을 camelCase로 써" 같은 **표기 규약 지침을
왜 자주 어기는가?**

**주장:** 지침을 "덜 봐서"가 아니다. 지침은 충분히 읽힌다. 문제도, 바로잡는 손잡이도
**모델이 어느 토큰을 얼마나 보느냐(어텐션 배분)가 아니라 그 자리에서 전달되는 내용(Value)**에,
그리고 **후반의 특정 층**에 있다. 그래서 어텐션을 키우는 기존 접근(Spotlight·PASTA)은
이미 충족된 조건을 더 채우는 셈이 된다.

| | 질문 | 스텝 |
|---|---|---|
| **RQ1** | 선행 코드에 지침을 위반한 함수명이 포함되면 준수율이 낮아지는가 | step1 |
| **RQ2** | 표기 정보는 Key와 Value 중 어느 경로로 전달되는가, 어느 층인가 | step2(관측) · step3(인과) |
| **RQ3** | 지침의 영향력도 같은 통로인가 | step4(관측) · step5(인과) |

**step6은 RQ가 아니다.** RQ1~3의 답에서 도출한 처방이고, 그 답이 옳았는지를 되짚는 검증이다.
**diag도 실험이 아니다.** step3·step5가 공유하는 치환 장치를 검사한 것이다.

## 2. 스텝 사슬 — 무엇이 무엇을 불렀나

각 스텝의 `results.md` 끝에 「다음 실험으로」가 붙어 있고, 그 사슬을 한 줄로 줄이면 이렇다.

```
step1  준수율이 임계에서 무너진다                → 신호가 어디로 오는지 모른다
  └→ step2  어텐션으로 관측                      → 자리 효과로 철회. 관측으로는 못 가른다
       └→ step3  Key/Value를 따로 덮어쓴다        → Value · 후반 단일 층
            ├→ diag   그 Key 결과가 장치 탓인가    → 기각. step3 결론 확정
            └→ step4  지침은 보기는 하는가         → 코드보다 더 본다 (관측의 한계)
                 └→ step5  지침을 덮어쓴다         → Value · 층 하나. 코드와 같은 구조
                      └→ step6  그러면 거기를 밀면  → 셋에서 회복 · 어텐션 증폭은 실패
```

**논문 서술 순서:** RQ1 → RQ2 → RQ3 → 처방(step6). 장치 검사는 검증 절에 붙인다.
**실행 순서(GPU 가벼운 것부터):** step2 → step4 → step1 → step3 → step5 → diag → step6.

## 3. 고정 설정 (모든 실험 공통)

### 모델 4개

| 이름 | 종류 | 역할 |
|---|---|---|
| Qwen2.5-Coder-3B-Instruct | 코드 전용 | 기준(주 분석) |
| deepseek-coder-6.7b-instruct | 코드 전용 | 매개변수 규모 차이 |
| stable-code-instruct-3b | 코드 전용 | KV 그룹 구조 차이 |
| Llama-3.2-3B-Instruct (unsloth 미러) | 범용 | 코드 특화 학습 의존 여부를 보는 대조군 |

> unsloth 미러를 쓰는 이유: 원본 Llama는 로그인·승인이 필요한데 unsloth판은 같은 모델이면서 그게 없다.
> 개입이 KV 그룹 단위로 수행되므로 매개변수 규모와 KV 그룹 구조가 서로 다르도록 선정했다.

### 데이터 — 함수 이름 504개

- **동사 50 × 명사 50** 조합에서 겹치지 않게 고른 **504개** (`parseHeader` / `parse_header`)
- 한 단어 이름은 두 표기에서 같아 제외. 매개변수와 본문은 전 항목 동일 — **이름 표기만** 변수
- 12개씩 **42묶음**. 묶음 하나가 반복 단위이고, 보고 값은 42묶음 평균과 95% 신뢰구간

### 그 밖

| 축 | 값 |
|---|---|
| 무작위 고정값(seed) | **42** (배치 순서만 정한다. 어느 이름을 쓰는지는 묶음이 정한다) |
| 내부 값 치환 | **평균 덮어쓰기(mean-pool)** — 반대쪽 조각들을 평균 내 바꿀 단어 전 자리에 덮는다. 토크나이저 무관, 코드·지침 동일. **KV 그룹 단위** |
| 적재 | float16, 양자화 없음, eager 어텐션, temperature 0.0 |
| 측정 지표 | 준수율 / 어텐션 / 영향력 / 되돌림률 / 어느 층 (정의는 `측정_정의.md`) |
| 통제 | 치환 실험은 **반드시 통제 공여를 함께 돌린다.** 보고는 **처치 − 통제(순효과)** |
| 판정 불가 | `\|S_깨끗 − S_기준\| < 1.0`이면 제외. `gap`·`undecidable`이 결과에 저장된다 |
| 언어 | **전 스텝 파이썬.** 하네스는 자바스크립트를 지원하지만 JS 결과는 0개다 |

## 4. 저장소 규약

- **브랜치는 `main` 하나다.** 실험 당시 브랜치는 `exp/*`·`local/*` 태그로 보존돼 있다
- **결과는 불변.** 저장 경로는 `results/<스텝>/<슬러그>.json` 하나뿐 (모델별 폴더로 나누지 않는다)
- **RQ별로 스크립트를 나누지 않는다.** 모든 실험이 `src/harness`의 `run(condition, mode=...)`를
  조건값만 바꿔 호출한다
- **조용한 실패 금지.** 미지원 개입, 치환 자리 0개, 관측 구간 못 찾음은 전부 예외를 던진다
